# AI Radar Intel Feed Design

日期：2026-04-25

## 背景

当前 PromptForge 已经覆盖了图库、预设、工作流、测试台、画师参考与法典库，但这些模块主要解决“已有资源如何整理与复用”的问题，没有覆盖“新信息如何持续进入系统”。

对个人 AI 学习而言，当前最大的瓶颈不是单点功能缺失，而是情报输入链路太弱：

1. AI 相关领域更新速度极快，知识半衰期短
2. 信息源高度分散，且不同圈层之间几乎没有统一社区
3. 生图、TTS、Agent、视频、多模态、论文、公司动态和小道消息往往分布在完全不同的平台
4. 仅依赖手工刷群、刷推、刷站点，会导致严重的信息滞后与认知断层

因此需要在 PromptForge 中新增一个附属页面，承担“个人 AI 情报流”的角色。

## 产品定位

首版定位：

`AI 雷达页 = 自用的高密度 AI 情报流页面`

它的目标不是帮用户自动做价值判断，也不是做完整知识库，而是：

1. 尽可能快地收集高价值 AI 相关动态
2. 尽可能广地覆盖关键平台
3. 尽可能清晰地按来源、领域、时间、可信度组织信息
4. 让用户能够基于情报流自行判断价值

## 首版目标

1. 新增一级页面，例如：
   - 页面名：`AI 雷达`
   - 路由建议：`/radar`
2. 以“情报流”而不是“知识库”形式展示内容
3. 首批覆盖六类来源：
   - `GitHub Releases / GitHub Trending`
   - `Hugging Face`
   - `Twitter/X`
   - `Reddit`
   - `B站`
   - `YouTube`
4. 采集策略采用：
   - `半自动聚合`
   - `重点名单驱动`
5. 页面支持按领域筛选，而不是按平台割裂查看

## 非目标

1. 首版不做“自动替用户判断价值”
2. 首版不做复杂知识图谱或向量检索
3. 首版不做自动总结为长报告
4. 首版不做全平台全量抓取
5. 首版不做公开产品形态，只服务自用

## 信息来源策略

### 1. 平台优先级

首批重点平台：

1. `GitHub`
2. `Hugging Face`
3. `Twitter/X`
4. `Reddit`
5. `B站`
6. `YouTube`

### 2. 首版采集原则

不追求“抓整个平台”，而是优先围绕“重点名单”采集：

- GitHub：重点仓库、组织、Release、Trending
- Hugging Face：重点组织、模型页、Space、热门更新
- Twitter/X：重点账号、列表、关键词流
- Reddit：重点 Subreddit
- B站：重点 UP 主、AI 分区、关键词搜索结果
- YouTube：重点频道、AI 相关关键词流

### 3. 采集形态

首版采用 `半自动聚合`：

1. 能稳定结构化抓取的先自动化
2. 不稳定或限制过强的平台，先采用：
   - 订阅名单
   - RSS/公开页面
   - 定向搜索结果页
   - 手动补录入口

## 页面形态

### 1. 页面结构

推荐布局：

- 顶部：
  - 今日 / 7天 / 30天
  - 全局搜索
  - 刷新情报流
- 左侧：
  - 领域筛选
  - 来源筛选
  - 可信度筛选
- 中间：
  - 情报流主列表
- 右侧：
  - 当前筛选统计
  - 快速收藏 / 稍后研究 / 已读状态

### 2. 首版领域分类

建议的高层分类：

- `通用大模型`
- `图像生成`
- `视频生成`
- `TTS / 语音`
- `Agent / 自动化`
- `训练 / 微调`
- `论文 / 研究`
- `公司动态`
- `传闻 / 爆料`
- `工具 / 社区`

### 3. 情报卡片字段

每条情报卡片首版建议至少包含：

- 标题
- 来源平台
- 原始作者 / 账号 / 仓库 / 频道
- 发布时间
- 领域标签
- 简短摘要
- 链接
- 热度或关注指标
- 可信度等级
- 是否为：
  - 新模型
  - 新项目
  - 新论文
  - 新教程
  - 新工具
  - 爆料 / 讨论

## 数据模型建议

首版建议新增独立数据域，例如：

### radar_sources

存放订阅源或重点名单：

- id
- provider
- source_type
- name
- url
- enabled
- sync_strategy
- metadata_json

### radar_items

存放采集后的情报项：

- id
- source_id
- platform
- category
- title
- summary
- content_preview
- author
- source_url
- published_at
- discovered_at
- heat_score
- credibility_score
- tags_json
- raw_payload

### radar_user_flags

存放个人状态：

- item_id
- is_read
- is_saved
- is_archived
- note

## 排序与去重

### 1. 排序

首版默认按以下权重混排：

- 发布时间
- 来源权重
- 热度权重
- 用户关注名单权重

### 2. 去重

必须做基础去重，否则多平台转载会淹没信息流。

建议规则：

1. 完全相同 URL 去重
2. 相同标题 + 相近时间的弱去重
3. 对“同一项目在多个平台被讨论”的情况不强制合并，但要标注为相关项

## 与现有 PromptForge 模块关系

首版只做弱联动，不强耦合：

1. 情报流中的模型、项目、工作流条目，可预留“加入稍后研究”
2. 后续可考虑再与以下模块联动：
   - `工作流`
   - `提示词预设`
   - `法典库`
   - `画师参考`
   - `测试页`

当前不要求首版直接把情报项导入这些模块。

## 分阶段实施建议

### Phase 9A：情报流基础设施

目标：

1. 定义 `radar_*` 数据模型
2. 新增主进程服务、IPC、preload 暴露
3. 新增 `/radar` 一级页面
4. 先支持本地存储、列表查询、筛选与标记已读

### Phase 9B：首批来源接入

目标：

1. 接入 GitHub Releases / Trending
2. 接入 Hugging Face
3. 接入 Reddit
4. 页面中可看到真正的自动采集结果

### Phase 9C：视频与社区源补充

目标：

1. 接入 B站
2. 接入 YouTube
3. 接入 Twitter/X 的可行公开链路或名单驱动抓取

### Phase 9D：个人化收口

目标：

1. 增加重点名单管理
2. 增加稍后研究 / 收藏 / 已读
3. 增加基础可信度与热度规则

## 首版明确边界

首版不要做：

1. 自动深度摘要日报
2. 自动给出投资建议式结论
3. 自动抓取私有群聊
4. 全平台账号登录整合
5. 全自动高频定时调度

## 验收标准

1. 新增 `AI 雷达` 一级页面
2. 首版能看到稳定的 AI 情报流，而不是空页面壳
3. 至少有 3 个自动化来源可用
4. 能按时间、领域、来源做筛选
5. 用户能快速判断：
   - 这是什么信息
   - 来自哪里
   - 属于哪个方向
   - 是否值得继续点开看
