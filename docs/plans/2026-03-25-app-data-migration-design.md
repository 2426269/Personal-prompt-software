# 应用数据目录迁移设计

日期：2026-03-25

## 背景

当前 PromptForge 默认将数据库、图片缓存、导出目录都放在系统 `AppData\Roaming\promptforge` 下。对长期使用者而言，图片缓存和工作流原始数据会持续增长，导致系统盘空间压力明显上升。

## 目标

新增“迁移应用数据目录”能力，将以下内容整体迁移到用户选择的新目录：

- `promptforge.db`
- `cache/`
- `exports/`
- 其他应用数据子目录

同时保留现有“备份导出 / 导入恢复”能力。

## 方案

### 1. 启动时目录覆盖

引入一个独立于 `userData` 目录之外的 bootstrap 配置文件，用于记录“当前实际应用数据目录”。启动时优先读取该配置，并在数据库初始化前调用 `app.setPath('userData', targetPath)`。

这样数据库、缓存、导出、日志目录都可以继续沿用 `app.getPath('userData')` 这一统一入口，不需要在业务层散落硬编码路径。

### 2. 设置页迁移入口

设置页在“存储与备份”区新增：

- 当前应用数据根目录
- 默认应用数据根目录
- 迁移应用数据目录按钮

迁移流程：

1. 用户选择一个空目录
2. 对当前数据库执行 `wal_checkpoint(TRUNCATE)`
3. 关闭数据库连接
4. 递归复制整个应用数据目录到目标目录
5. 写入 bootstrap 配置
6. 将当前进程的 `userData` 路径切换到新目录
7. 重新初始化数据库

### 3. 安全约束

- 目标目录不能与当前目录相同
- 目标目录不能与当前目录互为父子目录
- 目标目录必须为空，避免误覆盖
- 迁移失败时恢复原 `userData` 路径并重新打开旧数据库
- 成功后不自动删除旧目录，只提示用户手动清理，避免误删

## 工作区清理

本轮同时清理仓库根目录中的可再生产物，并补充 `.gitignore`：

- `out-app*`
- `out-win`
- `out-asar`
- `dist-app`
- `dist-preload`
- `temp-*`
- `build_log*.txt`
- `err*.txt`
- `trace.txt`
- `strict_err.txt`
- `run_*.txt`
- `win_err.txt`

目标是让 `git status` 恢复干净，同时释放本地磁盘空间。

## 验收标准

- 设置页可显示当前/默认应用数据目录
- 可将整个应用数据目录迁移到非系统盘空目录
- 迁移完成后数据库、缓存、导出目录都指向新位置
- 数据库查询、远端扫描、导出等功能在迁移后仍可正常工作
- 工作区历史构建和诊断垃圾已清理，`git status` 保持干净
